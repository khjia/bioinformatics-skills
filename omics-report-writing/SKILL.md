# 组学论文报告写作

**精简叙述，不删证据。** 默认交付一份中文全流程报告、完整样本补充表、按证据编号的图与独立图注，以及投稿待补项。写给刚接触这个项目的读者；让审稿人能从每条重要结论追到产物。用户指定语言、格式、期刊或取舍时遵照其要求。

## 从哪份材料开始

- Bulk RNA-seq：先读 [RNA-seq 指标与方法](references/rnaseq-publication.md)；用 [论文报告模板](templates/paper-report.md) 组织正文。逐样本表使用 [表 S1 表头](assets/table-s1-rnaseq-qc.tsv)，可用 `scripts/validate_rnaseq_qc.py` 校验。
- 全基因组重测序或组装：读 [重测序与组装指标](references/genome-reporting.md)，复用报告结构，不把 RNA-seq 指标、阈值或脚本套过去。

## 1. 先核对证据，再写

1. 以实际进入分析的样本表与矩阵列为准，连接原始文件、执行日志、输出、图表。分清母项目与当前样本，逐个记录纳入或排除及理由。别用同名文件猜配对或把母表范围填入子项目。
2. 建立证据账本：`结论或指标 | 样本/对比 | 单位、分母、阈值 | 来源 | 核验等级 | 限制`。区分运行日志、归档命令、脚本默认值、文件头或存在性核对、由明细复算、缺失或不可核验。表与记录不一致，先追溯；解释不了就写冲突，不自行择数。
3. 通常只读已有产物，不重跑流程或重新定阈值。缺失写「未确认」「未核验」或 `NA`，不当作零、不写成阴性结果。不开启新数据传输、不改原数据、不擅自提交归档。用户需要上传数据或重算，须另行明确范围。

## 2. 写成一条完整的证据链

由研究设计开始，沿 **原始输入 → 样本质控 → 比对或组装 → 定量或变异 → 模型与下游 → 结论** 顺序组织。每一节交代 **输入｜实际方法｜过滤条件｜得到什么｜对应图或表**。没有新增证据的步骤可共用表或引用下游图，不硬凑一张图。按项目实际结果选择图，不固定数量；不编造未分析的步骤。

- **正文：** 说清这步为什么做、读图看什么、证据支持到哪。首次出现术语时用一句话解释。图展示趋势，表保留精确值，正文不把图表逐项重念。
- **补充表：** 每个样本一行，保留用户需要的字段和数据源。不默认做全样本来源或中间产物的逐条展开页；定位信息进表或方法的来源索引。RNA-seq 样本质控主表默认不加计入基因的片段数或非零基因数，除非用户明确要求。
- **模型与下游：** 写明比较方向、基线、分母、模型、效应量和校正后显著性阈值。旧产物只有核对过前景、背景、方向与版本才可接入当前报告。区分统计显著与效应幅度；下游无方向富集不等于激活；共表达不是直接调控。
- **局限：** 组别与批次完全混杂、没有同时点对照、缺少独立验证等，要放在相关结果旁，而不是只藏在附录。逐句把因果表达限制在设计可支持的范围内。

## 3. 交付与核对

- 正文按目标格式导出；补充表优先 TSV；如有图，提供可单独导出的期刊兼容图与图注。图注明确样本量、单位、分组、分母、阈值、缺失点或误差的定义。
- 核对样本 ID 恰好出现一次、组别与源记录一致、原始和清洗口径成对、表图与来源能对上。用样本原始分子/分母复核汇总，不将平均值冒充加权率。报告中注明是复核已存在数据、读日志还是重算。
- 用文献确定常见报告项目，用期刊指南确定提交规格；不把其他研究的 QC 阈值当成此项目的合格线。投稿缺项集中列出：实验元数据、参考和软件版本、代码与数据可用性、归档编号。没有提交，就不写已归档。
- HTML 检查窄屏、表格筛选、图例和离线展示；论文图检查字是否清楚、分组是否不依赖颜色、截断或选择是否在图注说明。数字、陈述和验证状态不夸大。
